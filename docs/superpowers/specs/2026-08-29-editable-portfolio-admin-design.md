# 冯新波个人主页可视化编辑后台设计

## 目标

为现有 `fengxinbo558.github.io` 增加一个独立、轻量的可视化编辑后台。冯新波不需要修改 HTML、CSS 或 JavaScript，即可编辑主页中自己的文字、链接、项目、文章、联系方式、决策路径和头像，并将修改直接发布到线上主页。

后台继续依托现有 GitHub Pages 仓库，不搭建额外服务器、不引入数据库，也不改变当前桌面工作台式主页的视觉方向。发布由 GitHub 官方 Repository Contents API 完成；GitHub Pages 继续负责把 `main` 分支中的最新内容发布到公网。

## 已确认方案

采用“静态后台 + 结构化内容文件 + GitHub Contents API”的方案：

- 公开主页从仓库根目录的 `content.json` 读取个人内容。
- 新增 `/admin/` 编辑页，用表单编辑同一份内容并实时预览。
- 用户每次进入后台粘贴一个只授权当前仓库的 GitHub fine-grained personal access token。
- 点击“发布更新”后，后台通过 GitHub API 提交 `content.json`；若头像有变化，再提交头像文件。
- Token 只保存在当前后台页面的 JavaScript 内存中，不写入浏览器长期存储、页面地址、仓库或日志；刷新或关闭页面后自动消失。

该方案不采用独立 OAuth 服务，因为它需要额外部署和维护后端；也不采用下载 JSON 后手工上传，因为那仍然要求用户操作仓库，无法满足“一键同步上线”。

## 用户入口与页面结构

### 公开主页入口

现有底部状态栏增加一个低调的齿轮按钮，文字为“编辑内容”。按钮在桌面和手机端都可用，点击后在新页面打开 `/admin/`。公开访客可以看到入口和公开内容，但没有仓库 Token 就不能发布修改。

编辑入口不改变 ABOUT、WORK、NOTES、CONTACT 四个主视图，也不影响现有启动动画、头像拖拽和响应式布局。

### 后台布局

后台采用与主页一致的浅色桌面系统视觉，但以清晰、易填为第一目标。桌面端分为左侧分类、中央表单、右侧实时预览；手机端按“分类 → 表单 → 预览”纵向排列。

顶部固定显示：

- 返回主页
- 当前连接状态
- 未保存修改提示
- 清除 Token
- 发布更新

左侧分类包括：

1. 基本资料
2. 首页决策路径
3. 项目
4. 文章
5. 联系方式
6. 头像

第一次打开后台时先显示简短连接向导。用户粘贴 Token 后点击“连接 GitHub”，后台验证 Token 有效、能够访问 `fengxinbo558/fengxinbo558.github.io` 并读取最新内容；连接成功后才启用发布按钮。最终写权限由发布请求确认，若 Token 只有读取权限，后台会在发布时给出明确的 Contents 权限提示。

## 可编辑内容

### 基本资料

- 姓名
- 英文名或头像卡署名
- 职业名称
- 首页主张
- 能力概括
- ABOUT 辅助说明
- WORK 页标题、说明和 GitHub 总入口
- NOTES 页标题与说明
- CONTACT 页标题与说明

### 首页决策路径

- 中心节点标题与英文小标签
- 三条路径的左节点、右节点、颜色类型和说明；颜色类型限定为蓝、绿、金三种现有样式
- 路径可以调整顺序，但第一版固定为三条，避免破坏现有信息图布局

### 项目

每个项目可编辑：

- 标题
- 类型标签
- 项目说明
- 按钮文字
- 目标链接
- 状态文字

支持新增、删除、上移和下移。至少保留一个项目；第一项作为默认选中项目。

### 文章

每篇文章可编辑：

- 标题
- 分类
- 日期
- 原文链接
- 卡片序号
- 封面主文字、副文字和配色样式；配色限定为蓝、绿、金三种现有样式

支持新增、删除、上移和下移。文章可以为空；为空时主页显示“文章整理中”，而不是留下空白区域。

### 联系方式

每个渠道可编辑：

- 渠道名称
- 展示文字
- 链接
- 图标类型；限定为 GitHub、微信、邮箱、网站和通用链接

支持新增、删除和排序。联系渠道可以为空；为空时保留联系页说明，但隐藏渠道列表和主要联系按钮。

### 头像

后台同时提供头像路径输入和本地图片上传。路径只接受仓库内相对路径或 HTTPS 图片地址。上传支持 JPEG、PNG、WebP，单张不超过 3 MB；文件发布到固定的 `assets/profile-avatar.<扩展名>` 路径，同格式再次上传时更新原文件。选择文件后立即在预览区显示，但只有点击“发布更新”才会上传到仓库。现有 `avatar.svg` 仍作为默认和加载失败时的回退图片。

第一版只编辑内容数据和卡片顺序，不开放字体、颜色、整体布局、动画参数和导航结构，避免误操作破坏页面。

## 内容文件与主页渲染

新增根目录 `content.json`，它是公开主页的唯一可编辑内容源。文件按以下区域组织：

- `profile`：身份与首页文案
- `decisionSystem`：中心节点和三条决策路径
- `workSection`：WORK 标题与项目数组
- `notesSection`：NOTES 标题与文章数组
- `contactSection`：CONTACT 文案与渠道数组
- `assets`：头像路径
- `revision`：本次发布的时间标记，用于判断线上内容是否刷新

主页保留现有 HTML 文案作为加载失败时的静态回退。`script.js` 在启动交互前读取并校验 `content.json`，再把有效字段映射到现有页面节点。某个字段缺失或类型错误时，只回退该字段，不让整页失效。动态生成的文字统一用 `textContent`，链接只允许 `https:`、`http:` 和 `mailto:`，不把内容数据直接拼成可执行 HTML。

项目、文章和联系方式由各自独立的渲染函数生成。导航、启动动画、头像拖拽和项目切换逻辑只依赖渲染后的标准数据属性，不直接读取内容文件，从而保持内容层与交互层分离。

## 后台状态与编辑体验

后台维护四类独立状态：

- `remoteContent`：最近一次从 GitHub 读取的内容和文件 SHA
- `draftContent`：当前表单中的草稿
- `pendingAvatar`：尚未发布的新头像文件
- `connection`：Token、连接状态和发布状态

表单每次变化都更新草稿、实时预览和“有未发布修改”标记。切换分类不会丢失草稿；刷新或关闭页面前若有未发布修改，浏览器给出离开提醒。后台不自动发布，也不自动覆盖远端文件。

发布前执行以下检查：

- 必填的姓名、职业名称和主页主张不能为空
- 项目至少一个
- 决策路径恰好三条
- 所有外链协议合法
- 文本不超过明确的硬限制：单行字段 120 个字符，多行说明 600 个字符，链接 2048 个字符；姓名、职业、标题等紧凑字段另显示更短的推荐长度
- 头像格式与大小符合要求

输入较长时表单立即提示建议长度，预览仍显示实际效果。发布按钮附近提供可选的更新说明；未填写时使用“更新个人主页内容”。

## 发布流程

1. 后台用 Token 请求 GitHub API，读取最新的 `content.json`、其 SHA，以及必要的头像文件 SHA。
2. 用户编辑并预览草稿。
3. 点击“发布更新”后再次确认远端 `content.json` 的 SHA 未变化。
4. 若选择了新头像，先上传头像文件；头像成功后再将新路径写入草稿。
5. 将草稿编码并通过 Contents API 更新 `content.json`，提交到 `main` 分支。
6. API 返回成功后，清除未发布状态并显示“已提交，线上页面正在更新”。
7. 后台按短间隔检查公开站点的 `revision`，确认 GitHub Pages 已出现本次版本后显示“线上已同步”和主页链接；超过合理等待时间则提示稍后刷新，不重复提交。

头像与内容按顺序提交，不并行更新同一路径，避免 GitHub 文件更新冲突。若头像上传成功而内容提交失败，后台保留草稿和错误信息，用户可以重新发布；已上传但暂未引用的头像文件不会影响公开主页。

## Token 与安全边界

- 使用 GitHub fine-grained personal access token，仅授权 `fengxinbo558.github.io` 单个仓库，并仅开启 Contents 读写权限。
- Token 只作为发送给 `https://api.github.com` 的 `Authorization: Bearer` 请求头，不发送给公开主页、第三方分析服务或其他域名。
- 后台不加载第三方 JavaScript，不打印 Token，不把 Token放入错误消息。
- “清除 Token”会立即清空内存中的 Token、断开连接并禁用发布。
- 后台页面本身不是登录系统；安全能力来自 GitHub 对 Token 权限和有效期的控制。任何人都可以打开表单做本地预览，但只有拥有有效 Token 的人可以写入仓库。
- Token 建议设置较短有效期；发现泄露时应在 GitHub 设置中立即撤销。

GitHub 官方参考：

- [Authenticating to the REST API](https://docs.github.com/en/rest/authentication/authenticating-to-the-rest-api)
- [Keeping your API credentials secure](https://docs.github.com/en/rest/authentication/keeping-your-api-credentials-secure)
- [Repository contents API](https://docs.github.com/en/rest/repos/contents)

## 错误处理与恢复

- Token 无效或权限不足：保留当前草稿，指出需要检查的仓库和 Contents 权限，不回显 Token。
- GitHub API 限流或网络中断：保留草稿并允许重试，不重新上传未变化的内容。
- SHA 冲突：停止发布并提示“线上内容已被其他地方修改”；用户重新加载最新版后再编辑，不静默覆盖。
- 内容校验失败：定位到具体分类和字段，发布按钮保持禁用。
- 头像上传失败：不提交引用该头像的 `content.json`，公开主页继续使用旧头像。
- GitHub Pages 尚未刷新：API 提交成功与线上生效分开显示，避免用户误以为需要再次发布。
- `content.json` 无法读取或损坏：公开主页使用静态回退；后台显示恢复提示并允许用最后一次有效结构重新发布。

## 可访问性与响应式要求

- 编辑表单使用原生标签、输入框、文本域、按钮和文件选择控件。
- 所有错误信息与字段关联，发布状态使用可被辅助技术读出的实时区域。
- 连接、排序、删除和发布均可用键盘完成；删除需要明确确认。
- 焦点样式清晰，不只依赖颜色表达错误或连接状态。
- 390×844 手机视口下没有横向溢出，发布按钮和返回入口始终可达。
- 遵循 `prefers-reduced-motion`，后台预览不强制播放主页启动动画。

## 测试与验收标准

### 公开主页

- `content.json` 中的基本资料、三条决策路径、项目、文章、联系方式和头像都能正确映射到现有主页。
- 项目新增、删除和排序后，标签切换与键盘方向键仍正确工作。
- 文章或联系方式为空时出现约定的空状态，不报错。
- 内容文件缺失、字段缺失或格式错误时，静态回退内容仍可浏览。
- 不合法的链接协议不会生成可点击链接。

### 编辑后台

- 正确 Token 可以连接、读取最新内容并发布；错误 Token、权限不足、网络失败和 API 冲突都有明确提示。
- 所有表单改动会进入实时预览，并正确显示未发布状态。
- 新增、删除、排序项目、文章和联系方式后，草稿结构保持有效。
- 头像格式、大小、预览、上传失败和成功路径均经过验证。
- 关闭或刷新页面后 Token 不保留；点击“清除 Token”后所有发布请求立即失效。
- 发布过程中防止重复点击；成功后能区分“已提交”和“线上已同步”。

### 视口与回归

- 在 1440×900、1024×768、390×844 下检查主页和后台，无水平溢出、遮挡或不可达控件。
- 主页原有终端启动、四个视图切换、决策路径、项目标签、头像拖拽、外链和减少动态效果继续正常工作。
- 浏览器控制台无未处理错误。

## 非目标

第一版不提供多人账号、角色权限、修改历史界面、定时发布、文章正文托管、访客数据统计、主题设计器或任意 HTML 编辑器。GitHub 本身的提交历史承担版本追踪与回退；需要更复杂的多人管理时，再升级为带 OAuth 和服务端权限控制的独立后台。
